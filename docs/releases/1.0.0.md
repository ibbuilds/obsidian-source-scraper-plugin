# Source Scraper for Obsidian 1.0.0 — stable independent general-purpose plugin

**Stable standalone plugin release for Obsidian Desktop.** It operates as a general client of Source Scraper's public JSON schema v1. It does not include business rules for React, X, design, a particular vault or other personal workflow.

## Complete general-purpose workflow

- **Import:** versioned JSON/NDJSON entity exports from any supported Source Scraper project (including one-record NDJSON), validate boundaries and reject incompatible or dangerous data.
- **Inspect:** native Obsidian sidebar, search with preserved keyboard focus, original typed attributes, machine scores/confidence, human review decisions, and source evidence/history where present.
- **Configure projects:** neutral project-JSON editor with validation, exportable manifest as a **new create-only** file, optional read-only selection of existing project, without applying personal criteria.
- **Configure notes:** portable declarative JSON mapping for headings, user-selected additional YAML frontmatter fields and optional machine-assessment, attributes and provenance sections, no custom executable code.
- **Preview:** select records, inspect paths and rendered Markdown before writing.
- **Create:** explicit create-only Vault API files in a user-chosen folder, deterministic IDs, no deleting/renaming/overwriting even when source data or note mapping changes later.
- **Optional local CLI:** manually connect a trusted Source Scraper CLI, validate project, run authorized sources, import bounded JSON in memory, and explicitly save human reviews only for the matching project with a reason. JSON-only import works without CLI.
- **Safety:** no automatic network fetch or source process on Obsidian startup; no implicit outputs/webhooks or private vault migration.

## Candidate review fixes

- Preserve Unicode titles and entity identity keys even when CLI pipe chunks split a UTF-8 character; enforce response limits using received bytes.
- Reject common camelCase credential fields and credential-bearing query/fragment parameters before creating project files or note links. Ordinary document anchors and non-sensitive configuration fields remain supported.
- Keep the engine's `extract-links` default when loading a project that omits `pipeline`; the neutral starter explicitly chooses its own `observation-entity` pipeline.
- Keep the CLI execution lock until the cancelled process actually closes, with a bounded grace period before forced termination.

These changes are covered by focused regression tests. The implementation plan and migration inventory distinguish this candidate from the published 0.1.0 preview and keep personal-device acceptance and legacy retirement as separate gates.

## Verification and performance

The release candidate CI gates TypeScript, dependency audit, unit and adversarial-security tests on Linux/macOS/Windows, genuine Obsidian Desktop E2E in an isolated synthetic vault, and **actual** Source Scraper v0.14.0-beta.1 CLI integration (run, export, review, replay) with project and human-review state checked. It profiles a synthetic 4,000-entity JSON import and 200-note preview, rejecting gross performance regressions.

One earlier runner recorded **20.38 ms** to validate/import 4,000 synthetic records (~1.87 MB) and **4.35 ms** to render 200 notes. These are benchmark-specific measurements, not guaranteed hardware-wide results.

The release automation verifies the exact tested commit and three required assets. Unlike engine releases, historical plugin releases are preserved for rollback.

## Manual installation

Download `main.js`, `manifest.json`, and `styles.css` from the **same** release. Place them in `<vault>/.obsidian/plugins/source-scraper/`, then enable Source Scraper under Community plugins in Obsidian Desktop 1.9.2+. This is a manually installed plugin; **official directory listing/approval is not implied**.

## Explicit limits

This version supports **entity** JSON/NDJSON for the note-import workflow. The engine has other observation/alert/change datasets, but these are not silently misrepresented as entity notes. Automatic edits to existing notes, data migration, cloud sync, account-personalized X For You collection and X-specific recommendations are outside this plugin. The owner's personal-device installation has **not** been verified in CI. The previous `0.1.0` preview, legacy `x-feed-scraper` and all previous user notes remain untouched.
